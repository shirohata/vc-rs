# ストリーミングリサンプラーの設定改善案

記録日: 2026-09-06。**未実装・未評価の改善案**。現在の動作を変更する指示ではない。

## 現状と目的

`crates/vc-core/src/dsp.rs` の `StreamingResampleMono` は、入力レートに
関係なく480サンプルを要求し、FFT分割数1、窓関数 `BlackmanHarris2` を使う。
480サンプルは48kHzでは10msだが、16kHzでは30msになる。
入力レートに応じた時間単位の設定にして、特に16kHzから戻す経路の待ち時間を
減らせるか検討する。

rubato 3 → 5 の移行では旧設定を明示的に維持した。移行時の同一環境での
比較では、6種類のレート組み合わせ × 5種類の入力長 × 一括処理・3種類の
ストリーミング入力分割（計120条件）で、波形と出力長がビット単位で一致した。
この結果はライブラリ移行の確認であり、本改善案の音質・遅延を保証するものではない。

## 第一候補

- ストリーミングの要求チャンク長を「入力側の約10ms」にする。
  サンプル数への丸め方は実装時に明示する。
- FFT分割数1、`BlackmanHarris2` は維持し、変更する要素を絞る。
- 低遅延の比較候補として約5msも測定する。初めから既定値にはしない。
- `resample_mono` の一括処理は1024サンプル、`FixedSync::Both` のままにする。
  この関数はWAV専用ではなく、RVCの音量参照や接合処理にも使われる。

## 遅延の理論値

rubato 5.0.0 のFFTサイズ計算と `output_delay()` に基づく。
アプリ全体の実測遅延ではない。現在の入力チャンク時間は要求値であり、
内部FFTブロックの時間とは異なる場合がある。

| 変換 | 現在の入力チャンク時間 | 現在のフィルター遅延 | 約10ms指定時のフィルター遅延 |
|---|---:|---:|---:|
| 48k → 16k | 10ms | 5ms | 5ms |
| 16k → 48k | 30ms | 15ms | 5ms |
| 44.1k → 16k | 約10.9ms | 10ms | 5ms |
| 48k → 44.1k | 10ms | 5ms | 5ms |

`FixedSync::Input` の内部FFT入力サイズは、入力レートと出力レートの最大公約数を
`g` とすると、`ceil((chunk_size / sub_chunks) / (input_rate / g)) * (input_rate / g)`
で決まる（整数除算と最小値の扱いは上流実装を参照）。
出力遅延は `fft_size_out / 2` サンプル。
44.1k ↔ 16kのような組み合わせには最小FFTサイズがあり、要求チャンクを
半分にしてもフィルター遅延が減るとは限らない。

先頭の遅延サンプルを捨てても、必要な入力が揃うまでの待ち時間はなくならない。
フィルター遅延の差を、そのままアプリの往復遅延の改善量として扱わないこと。

## 新しい標準コンストラクターとの関係

rubato 5.0.0 の `Fft::new` は分割数を `max(chunk_size / 256, 1)` とする。
現在の480サンプルでは自動設定も1になり、窓関数も同じなので、
単に `new_custom` を `new` に戻してもストリーミング設定は変わらない。
また `FixedSync::Both` のFFTサイズ決定には分割数を使わない。
明示設定を続ける目的は、将来のデフォルト変更に動作を左右されないようにすること。

## 検証と採用判断

1. 旧設定・約10ms・約5msを、同じ入力とモデルで比較する。
2. 16k・44.1k・48k間の変換、短い入力、不規則な入力チャンクを含め、
   出力長、初回出力までの入力量、連続性、先頭の遅延補正、最終尾を確認する。
3. インパルス・周波数スイープ・高域信号で周波数応答と折り返し成分を確認する。
   小さいFFTでは高域の減衰特性も変わり得るため、歯擦音、高めの声、
   ノイズ除去後の実音声も試聴する。
4. 処理時間の平均と上位パーセンタイル、CPU負荷、バッファ不足、実際の
   入出力遅延を測る。処理回数が増えるので、小さいチャンクが常に高速とは限らない。
5. ノイズ除去の往復経路では初期充填量、遅延報告、停止時の排出・トリムを
   一緒に確認する。音質と出力整合性を保ち、実測上の利点がある場合に採用する。

## 関連箇所・変更時の制約

- `crates/vc-core/src/dsp.rs`: リサンプル設定、入力蓄積、先頭の遅延補正。
- `crates/vc-core/src/denoise/adapter.rs`: ノイズ除去モデルへの往復変換、初期充填と遅延。
- `crates/vc-core/src/model_rvc/stream.rs`: 16kHz入力への変換と音量参照。
- `crates/vc-core/src/sola.rs`: 接合処理に関係する一括リサンプル。
- `crates/vc-app/src/realtime.rs`: パススルーのデバイスレート変換。
- [アーキテクチャ](architecture.md): 共通パイプラインの所有境界。

変更は共通DSP層で行い、フロントエンド別の変換経路を追加しない。
音声コールバックに推論・リサンプル処理・割り当て・ロック・ログ出力を移さない。
定数変更時は入力バッファの整理閾値や各利用側の初期充填との関係も確認する。
